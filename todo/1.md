# 面向 RoPE KV Cache 的依赖感知非均匀变码率 IMI

## 1. 核心动机

普通 IMI（Inverted Multi-Index）的基本假设是：一个高维向量可以被切成多个近似独立的低维子空间，然后用这些子空间码字的笛卡尔积组成虚拟倒排桶。

但在大模型 KV cache 检索里，这个假设并不天然成立，原因主要有两个。

第一，Qwen/Llama 这类模型使用 RoPE。以 `head_dim = 128` 为例，RoPE 不是按相邻维度 `(0,1), (2,3)` 做旋转，而是 NeoX-style 的前后半维配对：

```text
(0, 64), (1, 65), ..., (63, 127)
```

因此，维度划分时不能把一个 RoPE pair 拆开。否则会破坏 key 在 RoPE 空间里的几何结构。

第二，不同 RoPE pair 之间的依赖关系并不相同。有些 pair 之间高度相关，或者在 attention logit 中经常共同起作用。如果把强依赖的 pair 切到不同 IMI 子空间里，IMI 的独立性假设会变差，导致大量低概率或空的虚拟桶，检索质量下降。

所以我们的目标不是手工设计一个非均匀切分，而是：

```text
以 RoPE pair 为最小单位，从校准数据中学习一种非均匀子空间划分，
使得不同 IMI 子空间之间尽可能独立；
然后根据每个子空间的维度和重要性，为其分配不同数量的聚类中心。
```

这个方法可以概括为：

```text
Dependency-Aware Variable-Rate IMI
```

中文可以叫：

```text
依赖感知的非均匀变码率 IMI
```

## 2. Key 的基本表示

对某一层、某一个 KV head，设 RoPE 之后的 key 为：

```text
k_i ∈ R^128
```

其中 `i` 是 token 位置。

由于 RoPE 的配对方式是前后半维配对，因此把 128 维 key 表示成 64 个 RoPE pair：

```text
p_{i,j} = [k_{i,j}, k_{i,j+64}] ∈ R^2
j = 0, ..., 63
```

所有 pair 的编号集合为：

```text
P = {0, 1, ..., 63}
```

我们希望把这 64 个 pair 划分成 `M` 个子空间：

```text
G = {G_1, G_2, ..., G_M}
G_a ∩ G_b = ∅
∪_i G_i = P
```

如果使用 8 个 IMI 子空间，则：

```text
M = 8
```

但每个子空间包含的 pair 数量不要求相同：

```text
|G_1|, |G_2|, ..., |G_8|
```

例如学习后可能得到：

```text
[16, 10, 9, 8, 7, 6, 5, 3]
```

这只是示例，不是预设。真实划分应该由模型、层、head 和校准数据决定。

## 3. 什么叫“子空间之间更独立”

IMI 的核心近似是：

```text
P(k) ≈ ∏_m P(k_{G_m})
```

也就是说，它假设不同子空间的分布可以近似相互独立。

因此，划分的目标应该是：让不同子空间之间的依赖尽量小。

设 `D(u, v)` 表示 RoPE pair `u` 和 RoPE pair `v` 之间的依赖强度，则理想目标是：

```text
min_G  Σ_{a≠b} Σ_{u∈G_a, v∈G_b} D(u, v)
```

也就是最小化跨子空间依赖。

等价地，因为总依赖量固定，也可以写成最大化组内依赖：

```text
max_G  Σ_m Σ_{u,v∈G_m} D(u, v)
```

这背后的逻辑是：

```text
强依赖的 pair 应该放在同一个子空间；
弱依赖的 pair 可以分到不同子空间；
这样 IMI 的 product-space 假设更接近真实 KV 分布。
```

这就是“非均匀划分”的核心理由，不是为了不均匀而不均匀。

## 4. 校准数据如何收集

划分应该从真实模型的 KV 分布中学习。校准数据需要尽量匹配目标任务：

```text
相同模型
相同 RoPE scaling / YaRN 设置
相同目标上下文长度
相似任务类型或数据分布
相同 dtype 路径优先
```

对每个 calibration prompt：

1. 运行 prefill。
2. 对每一层、每个 KV head，收集已经 RoPE 之后的 key：

   ```text
   K_{l,h} ∈ R^{seq_len × 128}
   ```

3. 如果要计算 attention-aware 指标，还需要收集 decode query：

   ```text
   Q_{l,h} ∈ R^{num_steps × group_size × 128}
   ```

4. 如果索引只覆盖 retrieval zone，则计算统计量时也应该只用 retrieval zone 的 key，排除 sink/local token。

划分粒度可以有几种选择：

```text
全模型共享一个划分
每层一个划分
每个 layer group 一个划分
每层每个 KV head 一个划分
```

推荐起步方案：

```text
每个 layer group、每个 KV head 学一个划分
```

例如 Qwen3-8B 有 36 层、8 个 KV head，可以把层分成：

```text
early:  0..11
middle: 12..23
late:   24..35
```

这样总共学习：

```text
3 个 layer group × 8 个 KV head = 24 个划分
```

这样既能反映层/head 差异，又不会引入过多元数据。

## 5. Pair 之间依赖程度如何计算

关键是定义依赖矩阵：

```text
D ∈ R^{64 × 64}
```

其中 `D(u, v)` 表示 pair `u` 和 pair `v` 的依赖强度。

### 5.1 基于 Key 分布的相关性

对 pair `u`，把所有 token 上的二维 pair 向量收集起来：

```text
X_u ∈ R^{N × 2}
```

对 pair `v` 同理：

```text
X_v ∈ R^{N × 2}
```

先对每个 pair 做 whiten 或标准化，然后计算交叉相关：

```text
C_{uv} = X_u^T X_v / N
```

依赖分数可以定义为：

```text
D_corr(u, v) = ||C_{uv}||_F
```

这个指标表示两个 RoPE pair 在 key 分布上的线性相关程度。

优点：

```text
简单
稳定
不需要 query
```

缺点：

```text
它只看 key 分布，不一定完全反映检索时的重要性。
```

### 5.2 基于 Attention Logit 的依赖

KV 检索真正关心的是 QK logit，而不是单纯重构 key。

对于 query `q_t` 和 key `k_i`：

```text
q_t · k_i = Σ_j q_{t,j:j+64} · p_{i,j}
```

定义 pair `j` 对 logit 的贡献为：

```text
s_j(t, i) = q_{t,j:j+64} · p_{i,j}
```

如果两个 pair 的贡献经常同时变大或共同影响 attention score，则它们不应该被拆到不同 IMI 子空间。

可以定义 attention-weighted dependency：

```text
D_attn(u, v) = E_{t,i} [ |s_u(t,i) · s_v(t,i)| ]
```

这个指标的含义是：pair `u` 和 pair `v` 在 attention logit 中的共同作用强度。

它比纯相关性更适合检索场景。

### 5.3 推荐的综合依赖矩阵

实际使用时，可以把 key 分布相关性和 attention 贡献相关性结合：

```text
D(u, v) = norm(D_corr(u, v)) + λ · norm(D_attn(u, v))
```

其中 `λ` 控制 attention 行为的权重。

推荐初始值：

```text
λ = 1.0
```

如果没有 query 数据，可以先只用：

```text
D = D_corr
```

## 6. 如何学习非均匀子空间划分

把 64 个 RoPE pair 看成图上的 64 个节点：

```text
node = RoPE pair
edge weight = D(u, v)
```

目标是把这个图划分成 8 个 group，使得组内边权尽量大、组间边权尽量小。

### 6.1 优化目标

设 `g(u)` 表示 pair `u` 被分到哪个子空间。

目标可以写为：

```text
max_g  Σ_{u<v} D(u,v) · 1[g(u)=g(v)]
```

也就是最大化组内依赖。

等价地：

```text
min_g  Σ_{u<v} D(u,v) · 1[g(u)≠g(v)]
```

也就是最小化跨子空间依赖。

### 6.2 约束条件

为了避免极端划分，需要设置每个子空间的最小和最大 pair 数：

```text
min_pairs ≤ |G_m| ≤ max_pairs
Σ_m |G_m| = 64
```

推荐初始配置：

```text
M = 8
min_pairs = 4
max_pairs = 16
```

这样允许非均匀划分，但避免出现一个子空间特别大、其他子空间过小。

### 6.3 RoPE 频率连续性正则

RoPE pair 的编号对应不同频率。相邻 pair 往往具有相近频率特性。

如果只看依赖矩阵，可能学出非常离散的 group，例如：

```text
G_1 = {0, 7, 19, 41, 63, ...}
```

这种划分虽然可能在统计上有高组内依赖，但实现上不友好，也可能不稳定。

因此可以加入一个弱的频率连续性正则：

```text
R(G_m) = Var({u | u ∈ G_m})
```

完整目标：

```text
max_g  Σ_m Σ_{u<v, u,v∈G_m} D(u,v)
       - γ · Σ_m R(G_m)
```

其中 `γ` 不应太大。依赖矩阵应该主导划分，频率正则只用于防止过度离散。

## 7. 实用求解算法

这个图划分问题不需要精确求解，可以用局部搜索。

### 7.1 初始化

可以从几种初始划分开始：

```text
均匀连续划分
按 RoPE 频率 band 划分
随机但满足 size constraint 的划分
```

使用多个 seed，最后选择目标函数最高的结果。

### 7.2 单点移动

每次尝试把一个 pair `u` 从当前 group `A` 移动到另一个 group `B`。

移动收益：

```text
gain(u, A -> B)
  = Σ_{v∈B} D(u,v)
    - Σ_{v∈A, v≠u} D(u,v)
    - γ · ΔR
```

只有满足以下条件才接受移动：

```text
|A| - 1 ≥ min_pairs
|B| + 1 ≤ max_pairs
gain > 0
```

### 7.3 两点交换

有些时候单点移动无法提升，但两个 group 之间交换 pair 可以提升。

尝试：

```text
u ∈ A, v ∈ B
swap(u, v)
```

如果交换后目标函数提升，则接受。

### 7.4 停止条件

当以下条件满足时停止：

```text
一轮遍历中没有任何 move 或 swap 被接受
或者达到最大迭代次数
```

最终得到：

```text
G_1, ..., G_8
```

这就是学到的非均匀 RoPE-pair 子空间划分。

## 8. 为什么 pair 多的子空间应该有更多簇

学到非均匀划分后，不同子空间的真实维度不同。

如果：

```text
|G_m| = n_m
```

则该子空间的真实维度是：

```text
d_m = 2n_m
```

例如：

```text
16 个 pair -> 32 维
6 个 pair  -> 12 维
```

如果所有子空间都使用相同的 `K`，高维子空间会被严重欠量化，低维子空间可能被过度量化。

因此应该为每个子空间分配不同数量的簇：

```text
K_1, K_2, ..., K_8
```

这就是 variable-rate centroid allocation。

## 9. 簇数 K_i 如何分配

不能只根据 pair 数量简单设定 `K_i`。更合理的是同时考虑：

```text
子空间维度
子空间重要性
子空间量化误差
总索引预算
```

### 9.1 子空间重要性

先定义每个 pair 的重要性：

```text
w_u = E_{t,i} |s_u(t,i)|
```

其中：

```text
s_u(t,i) = q_{t,u:u+64} · p_{i,u}
```

即 pair `u` 对 attention logit 的平均贡献。

子空间重要性为：

```text
w_m = Σ_{u∈G_m} w_u
```

### 9.2 Rate-Distortion 目标

设 `E_m(K_m)` 是子空间 `m` 使用 `K_m` 个 centroid 时的量化误差。

簇数分配目标：

```text
min_{K_1,...,K_M} Σ_m w_m · E_m(K_m)
s.t. Σ_m log2(K_m) ≤ B
```

其中：

```text
B = 总 bit budget
```

这个目标的含义是：

```text
在固定索引预算下，优先降低重要子空间的量化误差。
```

### 9.3 实际可实现版本

限制 `K_m` 只能从硬件友好的候选集合中选择：

```text
K_m ∈ {16, 32, 64, 128, 256, 512, 1024}
```

然后对每个子空间：

1. 分别训练不同 `K` 的 codebook。
2. 在 validation keys 上测量重构误差：

   ```text
   E_m(K) = mean ||x_m - nearest_centroid_K(x_m)||^2
   ```

3. 计算加权代价：

   ```text
   cost_m(K) = w_m · E_m(K)
   ```

4. 用动态规划或枚举选择 `K_1,...,K_8`：

   ```text
   minimize Σ_m cost_m(K_m)
   subject to Σ_m log2(K_m) ≤ B
   ```

最终得到：

```text
非均匀子空间: G_1,...,G_8
非均匀簇数:   K_1,...,K_8
```

## 10. 建立 Variable-Rate IMI

对每层/head 或 layer group/head：

1. 加载学到的 pair 划分：

   ```text
   G_1,...,G_8
   ```

2. 加载每个子空间的 centroid 数：

   ```text
   K_1,...,K_8
   ```

3. 对每个 retrieval-zone key `k_i`，按 group 抽取子空间向量：

   ```text
   x_i^{(m)} = gather_pairs(k_i, G_m)
   ```

4. 对每个子空间独立量化：

   ```text
   c_i^{(m)} = argmin_c ||x_i^{(m)} - C_m[c]||^2
   ```

5. 得到 key 的 IMI code：

   ```text
   code_i = (c_i^{(1)}, ..., c_i^{(8)})
   ```

6. 用 mixed-radix 编码得到虚拟 cell id：

   ```text
   cell_id = c_1
           + c_2 K_1
           + c_3 K_1 K_2
           + ...
   ```

7. 把 token id 加入对应倒排表：

   ```text
   inverted_list[cell_id].append(i)
   ```

虚拟 cell 总数为：

```text
K_total = Π_m K_m
```

这个数会非常大，但绝大多数 cell 是空的。因此实际实现应该只存非空 cell，可以使用：

```text
hash map
sorted compact cell table
CSR-like inverted list
```

## 11. 查询阶段

decode 时，对当前 query `q`：

1. 使用模型原生 RoPE 得到 RoPE 后 query。
2. 按同样的 pair group 抽取 query 子空间：

   ```text
   q^{(m)} = gather_pairs(q, G_m)
   ```

3. 对每个子空间计算 query 到 centroid 的分数：

   ```text
   score_m[c] = q^{(m)} · C_m[c]
   ```

4. 组合成 product-cell 分数：

   ```text
   score(cell) = Σ_m score_m[c_m]
   ```

5. 用 multi-sequence top-k 或 best-first search 找 top product cells。
6. 从这些 cell 的倒排表中取 candidate tokens。
7. 对候选 token 做精确 QK rerank。
8. 最终 attention 使用：

   ```text
   sink tokens + local tokens + retrieved tokens
   ```

由于子空间虽然非均匀，但仍然保持加性分解：

```text
q · k ≈ Σ_m q^{(m)} · centroid_m
```

所以 IMI 的快速 top-cell 搜索仍然成立。

## 12. 这个方法相比均匀 IMI 的优势

均匀 IMI 隐含假设：

```text
每个子空间同等重要
每个子空间维度相同
不同子空间近似独立
固定 K 足够表达所有子空间
```

但大模型 RoPE KV key 并不满足这些假设。

本方法显式建模：

```text
RoPE pair 不能拆
强依赖 pair 应该在同一子空间
不同子空间可以有不同维度
高维或重要子空间需要更多 centroid
划分和 K_i 都应该由数据学习
```

因此理论上可以改善：

```text
IMI 独立性假设
虚拟桶有效占用率
空桶比例
candidate recall
候选 token 质量
最终 attention 输出误差
```

## 15. 论文式贡献表述

不要把方法表述成“我们用了非均匀切分”。这太弱。

更强的表述是：

```text
我们发现 IMI 的 product-space 假设与 RoPE KV key 的 pair-wise dependency 存在冲突。
因此，我们以 RoPE pair 为最小索引单位，从校准 KV 分布中学习 dependency-minimizing 的非均匀子空间划分。
进一步，我们根据 attention-aware importance 和子空间量化误差，为不同子空间分配不同 centroid budget。
```

贡献点可以写成：

```text
1. RoPE-pair preserving IMI units
2. Dependency-aware non-uniform subspace learning
3. Attention-aware variable-rate centroid allocation
```

这三个点共同构成一个完整算法，而不是一个小的工程 trick。


› 很好做好了索引构建部分，对于搜索部分你有什么好的建议呢？


• 有。你这个索引的搜索部分不要只做“每个子空间 top-k，然后笛卡尔积枚举”。那样会很快遇到两个问题：

  1. 非均匀 K_i 下，不同子空间分数尺度不一致
  2. IMI 虚拟桶极多，大量 top cell 可能为空或候选质量不稳定

  我建议把搜索设计成 三阶段：校准分数、生成候选 cell、token 级 rerank。

  1. 子空间分数要做归一化
  每个子空间维度不同，score_m = q_m · c_m 的尺度天然不同。比如 32 维子空间的 dot product 方差会
  比 12 维子空间大。如果直接相加，大子空间会主导搜索。

  建议对每个子空间维护校准参数：

  μ_m, σ_m

  搜索时：

  raw_score_m[c] = q_m · C_m[c]
  score_m[c] = (raw_score_m[c] - μ_m(q)) / σ_m(q)

  更简单的版本：

  score_m[c] = raw_score_m[c] / sqrt(d_m)

  但更好的版本是在 calibration data 上统计每个子空间的 score distribution。这样 variable-rate
  IMI 才不会被大维度子空间压制。

  2. 不要枚举完整笛卡尔积，用 best-first top cell search
  有 8 个子空间，虚拟 cell 数是：

  K_1 * K_2 * ... * K_8

  不可能枚举。

  做法：

  1. 每个子空间先取 top L_m 个 centroid：

     T_m = top L_m centroids by score_m

  2. 每个 T_m 按分数降序排列。
  3. 用 priority queue 做 best-first search。初始状态是：

     r = (0,0,...,0)

     表示每个子空间的第一名 centroid。

  4. cell 分数：

     S(r) = Σ_m score_m[T_m[r_m]]

  5. 每次 pop 当前最高分 cell，然后扩展 8 个邻居：

     r + e_m

  这个就是 multi-sequence top-k / Fagin-style top product search。它适合你的 variable K_i。

  3. 搜索时要跳过空桶，最好用 occupancy-aware score
  IMI 最大问题是 top product cell 可能为空。你的非均匀划分会缓解，但不会消除。

  每个 cell 维护：

  n_cell = cell 中 token 数

  搜索 cell 时不要只看 query-centroid score，可以加一个 occupancy prior：

  S_cell = Σ_m score_m[c_m] + β log(1 + n_cell)

  或者更保守：

  如果 n_cell = 0，直接跳过

  我更建议：

  先跳过空桶；
  对非空桶加一个很小的 log occupancy prior。

  这样可以避免大量时间浪费在空 cell 上，也能让搜索更稳定。

  4. 候选 token 数要自适应停止
  不要固定访问多少个 cell。应该根据候选 token 数和分数边界停止。

  维护：

  candidate_set
  best_unvisited_cell_score
  worst_candidate_score_after_rerank

  停止条件可以是：

  len(candidate_set) >= candidate_budget

  基础版足够用。

  更强的 early stop：

  best_unvisited_cell_score < rerank_threshold
  且 candidate_set 已达到最小数量

  实践里建议：

  min_candidates = final_topk * 2
  max_candidates = final_topk * 8

  比如 final attention 需要 2048 个 token，可以先收 4096 到 8192 个候选，再 exact QK rerank。

  5. Rerank 必须用 exact QK，不要只靠 IMI score
  IMI score 是 centroid 近似，而且你的子空间非均匀、K_i 不同，最终 token 级排序一定要回到 exact
  QK：

  score_token = q · k_token

  然后取 top R：

  retrieved = topR(score_token)

  最后 attention 用：

  sink + local + retrieved

  这一步可以保证近似误差主要只影响候选召回，不直接影响最终排序。

  6. 加一个 value-aware rerank 会更有创新
  如果你想搜索部分也有 novelty，不要只停在 exact QK rerank。可以加入 value-aware ranking。

  普通 top-QK 只看：

  q · k_i

  但 attention 输出是：

  softmax(QK) V

  你可以定义 token 重要性：

  benefit_i = exp(q·k_i / sqrt(d)) * ||v_i||

  或者更稳定：

  benefit_i = softmax_approx_i * ||v_i - v_local_mean||

  最终 rerank：

  score_i = q·k_i / sqrt(d) + α log(||v_i|| + eps)

  更推荐作为第二阶段重排：

  先 exact QK 取 top 2R
  再 value-aware 选 R

  这会让搜索目标从 “找高 logit key” 变成 “找对输出贡献大的 KV”，比普通 ANN 检索更有创新。

  7. 非均匀子空间下，可以做 adaptive L_m
  每个子空间的 top centroid 个数 L_m 不应该固定。大/重要子空间分配更多 centroid 候选：

  L_m ∝ log(K_m) 或 L_m ∝ sqrt(K_m)

  也可以按 query uncertainty 自适应：

  如果子空间 top1 和 top2 分数差距小，说明不确定性高，取更大的 L_m
  如果 top1 明显领先，取更小的 L_m

  定义：

  gap_m = score_m[1] - score_m[2]
  L_m = larger when gap_m is small

  这个很适合你的 variable-rate IMI，因为不同子空间的重要性和分数分布不一样。

  我建议的完整搜索算法
  可以命名为：

  Calibrated Occupancy-Aware Product Search

  流程：

  Input: query q, learned groups G_m, codebooks C_m, inverted lists

  1. 按 G_m 抽取 q_m
  2. 对每个子空间计算 centroid score
  3. 做 score calibration，避免大维子空间主导
  4. 每个子空间自适应取 top L_m centroids
  5. 用 priority queue 做 best-first product cell search
  6. 跳过空 cell，并加 occupancy prior
  7. 收集候选 token，直到达到 adaptive budget
  8. 用 exact QK rerank
  9. 可选 value-aware rerank
  10. 输出 retrieved tokens，与 sink/local 一起做 attention

  核心公式：

  S_cell(c_1,...,c_M)
  = Σ_m norm_score_m(c_m) + β log(1 + n_cell)

  token rerank：

  S_token(i)
  = q · k_i / sqrt(d)

  value-aware 版本：

  S_token(i)
  = q · k_i / sqrt(d) + α log(||v_i|| + eps)

  或者：

  benefit_i
  = exp(q·k_i / sqrt(d) - lse_approx) · ||v_i||

  最有创新的搜索点
  如果你想让搜索部分也能写成贡献，我建议主打两个：

  1. calibrated product-cell search:
     解决非均匀子空间下不同维度/不同 K_i 的分数不可比问题。

  2. output-aware reranking:
     用 value 信息选择对 attention output 更重要的 token，而不是只优化 QK recall。

  这两个和你的索引构建是配套的，不是小 trick。
