现在正确逻辑应该重新收敛成下面这件事：

  我们已经有 64 x 64 的 score 矩阵。
  score(i,j) 越高，pair i 和 pair j 越应该在同一个子空间。
  后面就是一个带约束的图划分问题。

  你说的三个原则基本对：

  1. score 高的 pair 放一个子空间
  2. M 越大，IMI 子空间组合能力越强
  3. 划分越均匀越好

  但第 2 点要加一句限制：

  M 越大越好，是在不切断太多高 score 边的前提下。

  否则 M=16 如果出现很多 singleton，虽然 M 大了，但把很多依赖关系切断了，也不一定好。

  下一步应该改成这样

  把 64 个 pair 看成 64 个图节点。

  node = RoPE pair
  edge weight = score(i,j)

  然后对每个候选 M 做划分：

  把 64 个节点分成 M 个子空间
  每个子空间大小尽量均匀
  最大化组内 score 总和

  目标函数应该是：

  \max_{\mathcal{P}}
  \sum_{G \in \mathcal{P}}
  \sum_{i,j \in G,\ i<j}
  s(i,j)

  约束应该是：

  每个 pair 必须出现一次
  不能有空组
  group size 尽量均匀

  比如：

  M=4   -> [16,16,16,16]
  M=8   -> [8,8,8,8,8,8,8,8]
  M=16  -> [4,4,4,4,4,4,4,4,4,4,4,4,4,4,4,4]

  这比之前的：

  [16,16,16,4,1,1,1,...]

  合理得多。

  评估指标也应该换

  不要再主看 normalized_leak。

  应该看这几个：

  within_score:
    被保留在同一子空间内部的依赖总分

  keep_ratio:
    within_score / total_score
    表示全局依赖保留了多少

  cut_ratio:
    1 - keep_ratio
    表示全局依赖切掉了多少

  top_edge_keep:
    score最高的一批 pair-pair 边，有多少被保留在同一子空间

  其中最重要的是：

  keep_ratio
  top_edge_keep

  因为我们真正关心的是：

  强依赖 pair 有没有被放在一起

  选择 M 的逻辑

  应该变成：

  在均匀划分约束下，
  选择满足 keep_ratio / top_edge_keep 阈值的最大 M。

  例如：

  M=4   keep_ratio=0.47
  M=8   keep_ratio=0.44
  M=16  keep_ratio=0.35

  如果你设：

  keep_ratio >= 0.42

  那就选：

  M=8

  而不是盲目选 M=16。

  如果 M=16 的 keep_ratio 仍然足够高，那才说明：

  M=16 既细，又没有严重切断依赖

  这才是我们想要的。

  所以我建议下一步

  1. 修改 partition 搜索逻辑，强制 balanced partition。
  2. 删除 singleton 偏置，不允许 [16,16,1,1,...] 这种结果作为主实验。
  3. 输出新的指标：

     M
     group_sizes
     within_score
     keep_ratio
     cut_ratio
     top_edge_keep@5%
     top_edge_keep@10%

  4. 对 M=4,8,16 先跑一版。
  5. 看浅层/中层/深层的 keep_ratio 曲线。
  6. 最终选：

     满足依赖保留阈值的最大 M

  一句话：

  现在后面不应该继续按 leak/random 指标走，而应该把问题改成“64 个 pair 的加权图均衡划分”：高 score 边尽量组内保留，同时
  M 尽量大。
